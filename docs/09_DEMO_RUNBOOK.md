# 09 발표와 데모 실행안

v0.3 구현 문서 · 2026-10-09 · 시연 미실행

## 1. 전달할 경험

“점검 완료라는 기록에서 남은 일을 확인하고, 승인된 작업을 다음 교대가 인수해 사람의 최종 확인까지 이어갑니다.”

F1의 질문, F2의 승인된 작업, F3의 책임 이전, F4의 해결 이력을 같은 Incident ID로 보여준다. 실제 설비나 센서와 연결했다고 표현하지 않는다.

## 2. 준비

- [Fixture](10_FIXTURES.md)의 모호한 점검 기록 시나리오, CV-03, 네 역할, 두 교대를 사용한다.
- 제보 전의 깨끗한 DB 상태와 실연 후의 결과를 분리한다. 실제 run·명령·Incident ID는 생성 응답에서 기록한다.
- 실제 모델 시연은 `AGENT_MODE=live`, 녹화는 `replay`, 자동 시험은 `fake`로 구분한다. live 실패를 fake 성공으로 바꾸지 않는다.
- 승인된 데모 SOP의 출처·버전과 조회 결과를 열 수 있어야 한다. 검색은 실제 검색어와 내용으로 결과가 달라져야 한다.
- 역할 전환은 서버 세션을 사용한다. 전환 후에도 과거 메시지 작성자와 승인자의 신분은 유지된다.
- 평가 앱 SHA, tested/deployed SHA, prompt·tool·dataset 버전과 실제 시연 시간을 [제출 인덱스](../SUBMISSION.md)에 기록한다.

## 4. 전주기 조작

1. 작업자가 소음·진동 원문을 접수한다. 접수 ID와 DB 재조회 결과를 확인한다.
2. AI가 점검 기록을 조회하고 실제 확인 범위를 질문하면 정비 담당자로 답한다.
3. “외관만 확인했고 추가 점검 결과는 없다”는 답변 뒤 새 run이 만든 후보를 확인한다.
4. 출발 책임자가 Action의 범위·담당·기한·완료 기준을 확인하고 승인한다. 정비 담당자로 착수한다.
5. 미해결 상태에서 출발 책임자가 인계를 생성한다. 수신 책임자로 전환해 해당 항목을 ACK한다.
6. 정비 담당자로 합성 작업 결과를 제출한다. 수신 책임자로 최신 내용을 읽고 해결 확인한다.
7. 같은 사건의 원문·질문·승인·ACK·결과·검증·case를 다시 연다.

## 5. 모델 지연과 장애 대응

질문과 답변 후 제안에 모델 대기가 두 번 생긴다. run당 60초는 상한이며 목표 응답 시간이 아니다. 두 구간을 실제 리허설로 측정한다. 4분을 넘기거나 네트워크가 불안정하면 같은 최종 앱 버전의 실제 실행을 2분 이내 영상으로 준비하고 녹화임을 표시한다.

원문이 저장됐는데 모델이 실패하면 사건을 성공 처리하지 않는다. Job 실패·재시도 화면과 보존된 원문을 보여주고, 녹화된 성공 실행은 별도 증거로 소개한다. 승인 반려나 RETURN은 “후속 검토 필요” 상태로 남으며 Phase 1에서 두 번째 작업을 생성해 시연하지 않는다.

## 6. 완료 증거

| 항목 | 현재 상태 | 실제 수행 후 남길 값 |
|---|---|---|
| 전주기 시연 | NOT_RUN | Incident ID, 명령·run ID, 앱 SHA |
| 실시간 리허설 | NOT_RUN | 실제 총시간, 모델 대기 두 구간 |
| 녹화 대안 | NOT_CREATED | 영상 경로·실행 버전·녹화 표시 |
| 외부 데모 접근 | NOT_VERIFIED | 다른 계정/기기 확인자·시각 |

추가 시연은 Phase 1 필수 검증이 끝난 경우만 선택한다. L4 충분한 입력 대조 사례가 있으면 불필요한 질문을 생략한 실제 차이를 보여준다. 시행하지 않은 성능·현장 효과를 발표하지 않는다.
