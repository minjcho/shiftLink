# 14 도입 가설과 가치 검증

v0.3 구현 문서 · 2026-10-09 · 현장 검증 미수행

## 1. 첫 도입 범위

교대가 있는 한 라인의 작업자·정비 담당자·교대 책임자를 대상으로, 점검 기록을 확인하고 미해결 작업을 인수하는 구간부터 검토한다. 구매자나 고객이 확보됐다고 가정하지 않는다. 해커톤의 합성 설비·SOP·작업 결과는 실제 안전성·생산성 효과를 증명하지 않는다.

## 2. 확인할 문제

| 질문 | 기록할 사실 |
|---|---|
| 최근 점검 완료 뒤 남은 일이 있었는가 | 실제 사례 또는 그런 문제는 없었다는 반례 |
| 누구에게 무엇을 다시 확인했는가 | 재연락 횟수·대기 시간·질문 이유 |
| 교대 때 책임자와 남은 일은 어떻게 확인하는가 | 기존 문서·메신저·정비 시스템과 수기 단계 |
| 기존 시스템이 이미 해결하는 부분은 무엇인가 | 기능 부족인지 사용·절차 문제인지 |
| 어느 판단은 반드시 사람이 해야 하는가 | 작업 승인·인수·해결·설비 제어 경계 |
| 도입하면 입력 부담이 늘어나는가 | 이중 입력과 추가 질문으로 생긴 부담 |

참여 유형은 REAL_FRONTLINE / RELEVANT_EXPERIENCE / ROLEPLAY / NONE으로 구분한다. 팀원의 역할 연기는 사용성 리허설이며 고객 검증으로 집계하지 않는다. 확인하지 않은 수치와 인용문은 만들지 않는다.

## 3. 파일럿 단계

| 단계 | 수행할 일 | 다음 단계 조건 |
|---|---|---|
| 준비 | 대상 업무·자료 이용 범위·SOP 책임자·접근/보존 정책 확인 | 실제 사용 권한과 사람 검토 지점 합의 |
| 기준 측정 | 기존 방식의 확인·인계·재연락을 같은 업무 유형에서 관찰 | 표본과 측정 정의 확보 |
| 읽기 보조 | 기존 시스템을 기준으로 사본을 조사하고 초안 제시 | 근거 오류·불필요한 질문·누락 분석 |
| 제한 사용 | 승인된 범위에서 질문·후속 작업·인계 보조 | 권한·정정·장애 대응을 실제 확인 |
| 도입 판단 | 품질·업무 부담·총비용 비교 | 효과가 없거나 위험이 크면 범위 수정/중단 |

외부 정비 시스템에 작업을 생성하는 연계는 별도 승인·멱등성·실패 복구 계약이 필요하다. 해커톤 내부 Action 생성 성공으로 외부 업무 연계를 완료했다고 설명하지 않는다.

## 4. 측정 정의

| 지표 | 측정 단위 | 해석 제한 |
|---|---|---|
| 담당 누락 | 미해결 사건 중 지정 책임이 없었던 건수/관찰 건수 | 표본과 관찰 기간 함께 공개 |
| 재연락 | 사건당 추가 확인 횟수·대기 시간 | 필요한 확인을 생략해 수치를 줄이지 않음 |
| 인계 시간 | 같은 정보를 확인하는 데 걸린 시간 | 역할·문서량·사건 난도를 통제 |
| 사람 최종 확인률 | 해결 처리 중 실제 검토 기록이 있는 비율 | 클릭만으로 검토 품질 입증 불가 |
| 모델 비용 | 성공 사건당 실제 input/output usage와 계정 단가 | 재시도·실패 호출 포함 |
| 전체 부담 | 도구 비용 + 사람 확인·이중 입력·운영 시간 | 모델 토큰만 절감했다고 총비용 절감 주장 금지 |

품질을 유지한 상태에서 비교한다. 모델·프롬프트·자료·스키마가 바뀌면 비교 조건과 영향을 기록한다. run 제한값과 성능 실측은 구분한다. 현재 값은 모두 미측정이며 [시험 양식](../templates/TEST_RESULTS.md)을 사용한다.

## 5. 운영 전 남은 과제

실제 인증과 사업장 권한, SOP 적합성, 데이터 정정·보존, 복수 사건·작업, 반려 후 재작업, 외부 연동, 악성 입력 대응, 계정 비용 제한을 검증한다. 실제 설비 제어나 산업 안전 승인은 현재 서비스 범위에 없다.
