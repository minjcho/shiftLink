# F1 PR 리뷰의 복구·동시성·조회·입력 제한 보완

Status: Ready

## 목표와 범위

PR #6에 등록된 다섯 리뷰를 수정하여 불확실한 접수의 중복, 조사 도구와 재시도의 교착, 과거 인계 요약 선택, 무제한 모델 입력, 무시되는 API 경로 설정을 방지한다. 사용자 요청은 기존 코드의 리뷰 수정과 해당 PR의 댓글 작성이며 신규 기능 추가가 아니다. 서로 다른 경계의 결함 다섯 개를 다루므로 단일 행 수정 이상의 회귀 확인이 필요하다.

현재 `apps/web/src/features/intake/IncidentList.vue`는 목록 조회 뒤 원 요청을 초기화한다. `apps/api/app/agent/tools.py`는 Job 잠금 후 Incident 하위 데이터를 저장하고, `features/intake/service.py`의 재시도는 반대 순서로 잠근다. 같은 파일의 상세 조회는 여러 인계를 정렬 없이 덮어쓴다. `agent/context.py`와 `runner.py`는 전체 누적 원문·근거를 입력 제한 없이 전달한다. `apps/web/src/lib/api.ts`는 설정과 무관하게 `/api/v1`로 요청한다.

DB 원문·근거·업무 상태·권한·receipt·lease·기존 응답 shape는 보존한다. 데이터 마이그레이션, F2/F3/F4 신규 구현, 원격 병합, 실제 모델 품질 평가와 배포는 범위 밖이다. 기존 기능 목표 문서와 당시 검증 기록은 변경하지 않는다.

## 결정과 근거

- 불확실한 명령은 조회 성공만으로 새 명령이 되지 않는다. 같은 키·본문으로 결과를 확인하며, 확정 거부 뒤의 명시적 새 제출과 계정 전환은 기존 구분을 유지한다. 근거: 사용자에게 보고한 리뷰 분석과 이를 바탕으로 수정하라는 현재 요청, [D05](../../11_DECISIONS_AND_SOURCES.md).
- 도구 저장도 Incident를 먼저 잠그며 실행 소유권 검사를 유지한다. 근거: [도메인의 잠금 순서](../../03_DOMAIN_MODEL.md), 리뷰의 재현된 경합.
- 단일 인계 요약은 사업장·참여자 권한을 만족하는 인계 중 생성 시각과 ID의 내림차순으로 첫 항목을 선택한다. 배열 응답으로 확대하지 않는다. 근거: 직전 분석의 최신 인계 한 건 제안과 현재 수정 요청, [F1 조회 권한](../f1-intake-investigation/SPEC.md).
- DB 원문은 잘라 저장하지 않는다. 모델에 필요한 현재 상태·trigger·질문/답변·작업·근거를 우선하고 부가 이력은 제한된 입력 안에서 선택한다. 생략된 출처는 본 것으로 기록하지 않는다. 필수 정보조차 담을 수 없으면 명확한 용량 오류로 종료하고 업무 후보를 확정하지 않는다. 근거: 직전 분석의 입력 예산 제안과 현재 수정 요청, [Agent 출처 계약](../../05_AGENT_DESIGN.md).
- API 경로 설정은 동일 출처의 비어 있지 않은 API prefix를 지원하고 미설정 시 `/api/v1`을 유지한다. 루트 경로는 UI 경로와 충돌하므로 지원하지 않는다. 근거: [환경 설정 계약](../../ENVIRONMENT.md)의 동일 출처 API 경로, 기존 SPA `/incidents` 경로, 이번 수정의 제한된 호환 범위.

## 사용 시나리오

| 종류 | 시나리오 | 조건 |
| --- | --- | --- |
| 흐름 | 제보가 저장된 뒤 응답이 끊겨도 담당자가 같은 요청의 결과를 확인하면 처음 저장된 사건으로 이동하고 사건이 추가 생성되지 않는다. | AC-1, AC-2 |
| 경계 | 목록 조회가 실패하거나 필터·페이지 때문에 원 접수를 보여주지 못해도 불확실한 요청의 키와 원문을 유지한다. | AC-1 |
| 경계 | 조사 도구의 근거·후보 저장과 담당자의 Job 재시도가 겹쳐도 정상 상태 응답과 일관된 데이터가 남는다. | AC-3 |
| 흐름 | 같은 사건의 여러 교대 인계에 참여한 책임자가 자신의 최신 인계 상태와 링크를 본다. | AC-4 |
| 경계 | 사건 이력이 길어져도 제한된 모델 입력에는 최신 필수 사실과 실제 전달한 근거만 남고 원문은 상세 조회로 보존된다. | AC-5, AC-6 |
| 흐름 | 공개 API prefix를 설정한 브라우저의 읽기·쓰기가 그 경로를 통해 실제 API에 도달한다. | AC-7 |
| 유지 | 확정 충돌 뒤 새 명령, 계정 전환, 권한·lease·업무 버전·기존 데이터 및 기본 실행 구성이 유지된다. | AC-2, AC-3, AC-8 |

## Acceptance Criteria

- **AC-1** 결과가 불확실한 제보는 조회 성공·실패와 무관하게 원 키와 본문을 유지한다. 원 제보가 실제 API·DB에 저장된 뒤 응답만 유실되어도 동일 요청 확인은 같은 사건 ID를 반환하고 Incident·Message·Job을 중복 생성하지 않는다.
- **AC-2** 확정된 버전 충돌은 최신 내용을 성공적으로 확인한 뒤 사람의 새 제출에서 새 키를 사용한다. 조회 실패·다른 조회에 밀린 응답은 초기화 근거가 되지 않는다. 계정 전환 뒤 이전 계정 명령이 자동 재전송되지 않는다.
- **AC-3** 실제 DB에서 근거 검색 저장 또는 작업 후보 저장과 같은 사건의 RUNNING Job 재시도가 겹쳐도 교착으로 실패하지 않으며, 실행 중 재시도는 정해진 409 응답을 반환한다. 만료되거나 바뀐 lease의 worker는 저장을 확정하지 못한다.
- **AC-4** 같은 사건의 여러 인계 중 참여자가 읽을 수 있는 최신 한 건이 삽입 순서와 무관하게 선택된다. 같은 시각에도 결과가 결정적이며 최신 인계의 비참여자는 자신에게 허용된 과거 인계만 볼 수 있다. 공개 응답에 snapshot·token이 노출되지 않는다.
- **AC-5** 긴 부가 이력과 누적 근거가 있어도 모델 입력은 설정된 총량 안에 머문다. 현재 업무 상태, trigger와 필요한 질문/답변·작업·근거의 연결을 유지하고 본문 중복을 피한다. 선택에서 생략한 근거는 해당 실행의 인용 가능 출처로 등록되지 않는다.
- **AC-6** 초기 입력뿐 아니라 도구 결과가 누적된 다음 모델 호출도 총량 제한을 지킨다. 필수 정보 또는 프로토콜을 온전히 담을 수 없으면 용량 오류를 명확히 기록하고 그 입력으로 모델 호출·업무 후보 확정을 하지 않는다. 저장된 원문·과거 근거·사람의 업무 상태는 손상되지 않는다.
- **AC-7** 기본값과 비기본 동일 출처 API prefix 모두 브라우저의 GET·POST에 적용되고 세션 쿠키와 멱등 키가 유지된다. 끝 슬래시를 정규화하고 외부 출처·루트·모호한 경로 설정은 명확하게 거부한다.
- **AC-8** 기존 F1의 원문 접수·지정자 답변·새 조사·재시작 복구·권한·버전·lease·원자성은 유지된다. 공유 DTO·enum·마이그레이션·이미 확정된 작업과 인수 책임은 바꾸지 않는다.
- **AC-9** PR #6에 수정 커밋이 반영되고 다섯 리뷰 각각에 수정 내용과 실제 검증 범위·한계를 설명하는 댓글이 존재한다.
