# 15 제출 준비와 버전 확인

v0.3 구현 문서 · 2026-10-09 · 제출 미수행

## 1. 공식 기준과 팀 내부 목표

[공식 행사 안내](https://luma.com/f7h7onav)의 개발·제출 마감은 17:00 KST다. 17:00~17:10은 운영진 확인 시간이며 추가 개발·제출 시간이 아니다. 예선은 발표·데모 합계 4분이다. 구체적인 제출 플랫폼·Codex 기록 형식·PDF 제한·심사자 권한은 최종 참가 안내를 확인한다.

팀 내부 목표는 15:00 이후 확장 착수 중단, 15:15 기능 동결, 16:40 접수 확인이다. 이미 지난 시간은 실제 완료 상태를 확인하고 다음 필요한 작업으로 진행한다. 기능 미완료를 완료로 바꾸어 기록하지 않는다.

## 2. 제출 대응

| 항목 | 기록 위치 | 준비·확인 책임 | 완료 조건 |
|---|---|---|---|
| 등록 저장소·평가 SHA | SUBMISSION | 공동 | 등록한 저장소의 정확한 전체 SHA와 대상 권한 열람 |
| Codex 사용 기록 | CODEX_WORKLOG와 운영진 요구 형식 | 각 기능 담당, 상대 검토 | 실제 지시·결과·사람 검토·수정·시험 연결 |
| 발표 PDF | SUBMISSION의 실제 경로 | 공동 | 구현·검증·한계·버전과 링크가 읽힘 |
| 데모 링크 | SUBMISSION | 공동 교차 확인 | 다른 기기/세션에서 핵심 흐름 접근 가능 |
| 사전·당일 구분 | PREWORK | 공동 | 출처·수령/반영 시점·당일 변경 구분 |
| 접근·공개 자료 확인 | SUBMISSION 체크리스트 | 공동 | 키·개인정보·비공개 원문 제외와 실제 권한 확인 |

위 표는 공식 제출물과 공개·접근 점검을 함께 정리한 내부 목록이다. 개별 공식 양식이 있으면 그것을 따른다. 제출 요청은 이번 문서 생성에 포함되지 않는다.

## 3. 버전 대응

아래 식별자는 실제로 확인한 뒤 기록한다.

- `evaluated_app_commit_sha`: 심사 대상 앱 소스.
- `tested_app_commit_sha`와 `working_tree_dirty`: 시험한 코드와 미커밋 변경 여부.
- `deployed_app_commit_sha`: 배포가 사용한 앱 소스.
- `model_id`, `prompt_version`, `tool_schema_version`, `dataset_version`, `knowledge_version`: 코드 밖 결과 결정 요인.
- `presentation_revision`, 녹화의 앱 SHA·모드: 발표·영상이 가리키는 구현 범위.

앱 코드를 C로 고정한 뒤 시험·배포한다. 결과·제출 인덱스를 문서 전용 후속 commit D에 기록하면 C와 D를 구분한다. `SUBMISSION.md`에 자기 자신의 최종 commit SHA를 쓰고 다시 commit하는 자기 참조 문제를 피한다. 프롬프트·실행 설정·코드가 바뀌면 문서 전용 변경으로 취급하지 않는다.

## 4. 순서

1. Phase 1 시험과 남은 실패를 확인하고 앱 버전 후보를 정한다.
2. 같은 코드·설정으로 필요한 회귀와 live를 실행해 결과를 기록한다.
3. 같은 버전으로 배포하고 다른 팀원의 환경에서 접속한다. localhost 접근은 외부 데모 검증이 아니다.
4. 결과에 맞춰 영상·PDF·Codex 기록·PREWORK·SUBMISSION을 채운다.
5. `.env`와 대화 원문을 제외하고 공개용 기록의 민감정보를 확인한다.
6. 실제 제출 시스템에서 제출한 뒤 접수 상태·시각·식별자를 확인한다.

배포·업로드·접수는 각각 별도 결과다. 링크 생성이나 업로드 완료만으로 접수됐다고 보고하지 않는다.

## 5. 대화 기록과 환경 파일

`docs/history/`는 사용자 요청에 따라 로컬 원문 보관용이며 Git에서 제외한다. `CODEX_WORKLOG.md`에는 필요한 실제 작업과 검토·검증 근거를 요약한다. 운영진이 원본 기록을 요구하면 지정 방식으로 필요한 범위의 공개용 사본을 준비하되 저장소의 ignore 규칙을 없애거나 `git add -f`로 원문을 추가하지 않는다.

`.env`·`.env.local` 등 비밀 환경 파일은 공개하지 않는다. `.env.example`은 설정 이름과 빈 비밀값·명확한 로컬 예시만 포함한다. 공개용 Web에는 비밀값을 넣지 않고 로컬 계정 전환 기능을 무제한 공개하지 않는다.
